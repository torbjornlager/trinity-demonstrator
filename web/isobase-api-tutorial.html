The ISOBASE API

A short tour of Web Prolog's stateless HTTP protocol. Every call carries everything needed to compute its answer.

One query, one HTTP request

?- append(Xs,Ys,[a,b,c]).

The direct API equivalent asks for one solution, starting at offset zero:

GET /call?goal=append(Xs,Ys,[a,b,c])&offset=0&limit=1&format=json
{
  "type": "success",
  "data": [{ "Xs": "[]", "Ys": "[a,b,c]" }],
  "more": true
}

There is no session identifier. The goal, source text if any, paging controls and execution options belong to this one request.

The next answer is another complete call

GET /call?goal=append(Xs,Ys,[a,b,c])&offset=1&limit=1&format=json
{
  "type": "success",
  "data": [{ "Xs": "[a]", "Ys": "[b,c]" }],
  "more": true
}

The node may cache work internally, but the protocol does not expose that cache. Repeating this URL still has the same meaning after a restart or on another equivalent node.

Calling it from JavaScript

const url = new URL("/call", location.origin);
url.search = new URLSearchParams({
  goal: "append(Xs,Ys,[a,b,c])",
  offset: "0",
  limit: "1",
  format: "json"
});

const answer = await fetch(url).then(response => response.json());
Select API traffic in the Logger before pressing CALL. You will see the stateless request and response generated by the demonstrator.

Within Prolog, rpc/2-3 offers a synchronous wrapper over this model; promise/3-4 and yield/2-3 provide the asynchronous form.

Advantages and disadvantages

AdvantagesDisadvantages
Self-contained, replayable requests; simple HTTP deployment; easy horizontal scaling; responses can be cached. No private state between requests; no interactive input; no control channel with which to abort a running request, so server-enforced timeouts matter.

Choose ISOBASE when a remote computation naturally fits a function-like request and answer. Move to ISOTOPE when a sequence of calls must share a private database or interactive toplevel.
