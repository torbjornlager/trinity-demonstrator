Web Prolog manual

This is the shared language and API manual for Web Prolog across native SWI-Prolog, native Trealla and the SWI-WASM browser runtimes. It describes common behaviour once and labels remaining implementation differences at the relevant entry. The language is a design in progress; a listed runtime limitation does not establish a separate language definition.

The classification shown beside each entry identifies the minimum public node profile in which the predicate is available, or another relevant execution context. ISOBASE provides general stateless Prolog calls, ISOTOPE adds persistent toplevel sessions, and ACTOR adds the full stateful actor-messaging model. The profiles are cumulative, so an entry marked isotope is also available in ACTOR. The classification concerns the client language, not predicates used internally to implement a profile. Entries additionally marked owner only are reserved for code running with node-owner authority and are not available to ordinary client code.

Each predicate entry has a stable anchor based on its indicator. Runtime architecture, setup, transport implementation and regression-test notes belong to the native SWI guide, Trealla guide and SWI-WASM guide. This web reference and Appendix B of the book present the same language manual. The book’s wire specification is in Appendix D; code examples are maintained separately.

Common conventions and runtime differences

“Native” means a server runtime running SWI-Prolog or Trealla. “SWI-WASM” means either the Worker runtime or the compatibility main-thread engine in the browser. Runtime choice is independent of the node profile. Browser actors live only as long as their page and cannot accept incoming node connections; native nodes can remain available independently of a browser.

Options and validation

The creation predicates, synchronous toplevel wrappers, first_solution/3, rpc/3, promise/4 and yield/3 validate their documented option lists. Lists must be proper and options recognised, with valid arities and values. Every occurrence is checked, including later duplicates. The first scalar setting takes precedence; repeated source options are additive. Validation preserves shared variables and does not execute goals or callbacks. Validation precedes source fetching, actor creation, request dispatch or promise collection, as appropriate. Other option lists follow their individual predicate entries.

Unknown options raise a domain error identifying the API's option family; invalid values raise instantiation, type or domain errors. Context terms and some formal error names differ by runtime. Runtime-only metadata is not a public option. An invalid yield/3 option leaves the promise available for retry.

Source loading

Source is loaded before its goal runs and remains private to the receiving actor or stateless call. Repeated source options preserve order within each source kind. Native SWI, Trealla and the browser main engine process source options in list order. Worker source collection groups text, clause lists, copied predicates and URI texts, in that order. Programs combining source kinds must account for this Worker ordering difference.

For native SWI actor creation, the destination loads URI source under its own fetch restrictions. Trealla materialises supplemental Prolog URI source on the calling node before remote dispatch. Browser actor creation fetches supplemental Prolog URI source in the creating browser engine and sends the resulting text to the child or remote node. RPC and promise source options are materialised by the calling runtime; for a promise this is done before the asynchronous request starts. Repeated URIs are fetched separately. Browser fetching is restricted by the page's origin allowlist and CORS; file access is unavailable. URI XML for a statechart is fetched by the engine or node that runs that chart. Root-relative XML URIs on native Trealla resolve against the destination's configured public URL.

Text source should use atoms or strings for portability. Native runtimes also accept some character/code-list text forms. Source predicates are identified by atom names and nonnegative integer arities. Source loading and execution remain subject to the destination's profile and sandbox; sender module names grant no authority. Blacklist mode remains a prototype policy rather than a complete security boundary.

Predicates for programming with core actors

Predicate: self/1
actor
self(-Pid) is det.

Binds Pid to the process identifier of the calling process.

Note: A pid is an actor address whose canonical global form is Id@Node, where Id is assigned by Node. This ordinary Prolog compound is part of the language contract: programs may copy, store, construct, decompose, compare, and serialise it. A shell may omit @Node for a pid on the shell's own node, but this is only a local abbreviation. Constructing a pid does not create an actor, confirm that it is live, or grant access to it; an operation reaches an actor only when the pair designates that actor and the node authorises the operation. Arithmetic on a numeric Id has no defined actor-level meaning. Browser runtimes reserve localhost as the local-node designator. Worker actors are therefore presented as, for example, 2159438818@localhost, and the optional main-thread SWI-WASM engine is presented as main@localhost.

Predicate: spawn/1-3
actor
spawn(+Goal) is det.
spawn(+Goal, -Pid) is det.
spawn(+Goal, -Pid, +Options) is det.

Creates a new Web Prolog actor process running a copy of Goal. The child pid is unified with Pid before copying the goal, so occurrences of that same variable within the goal carry the child pid. Repeated variables retain sharing within the copy, but no variable identity is shared between parent and child: bindings made by one do not bind variables in the other. The same rule applies to local and remote creation. Results cross the boundary explicitly, through messages or the toplevel protocol.

A principal subtree quota raises error(resource_error(actors),_). Contact loss during remote creation raises remote_spawn_failed(connection_closed); retrying effectful work requires application duplicate suppression.

Valid options are:

  • node(+URI)
    Creates the process locally or on a remote compatible node. Default is localhost.
  • monitor(+Boolean)
    If true, monitoring is installed as part of process creation. Default is false.
  • link(+Boolean)
    If true, installs directional parent-to-child link cleanup. Default is true. On a public node, only its owner may use link(false); detachment transfers ownership to the node and sends output to its log.
  • src_text(+AtomOrString)
    Loads the clauses specified by a Web Prolog source text into the actor's private Prolog database before calling Goal.
  • src_list(+ListOfClauses)
    Converts the clauses to source text and loads them into the actor's private Prolog database before calling Goal.
  • src_uri(+URI)
    Loads the clauses specified by a file path, file URI, or HTTP(S) URI into the actor's private Prolog database before calling Goal.
  • src_predicates(+ListOfPredicateIndicators)
    Loads the local predicates denoted by ListOfPredicateIndicators into the actor's private Prolog database before calling Goal.

Options follow the common validation rules. node/1 takes an atom or string; link/1 and monitor/1 take booleans. Source options follow source-loading conventions. Native SWI and Trealla plain spawn/3 do not accept name/1; their specialised creation predicates do. SWI-WASM plain spawn additionally accepts name(+Atom). Browser target/1 and io_target/1 are compatibility settings and do not redirect remote output.

Named creation reserves the caller’s ordinary name before starting the actor and publishes it only after successful setup. An occupied or pending name prevents creation; pending names are invisible to whereis/2 and cannot be cancelled by unregister/1. Failure or interruption releases the reservation and reclaims resources owned by that attempt. Publication guarantees neither continued liveness nor application readiness. A remote name is an alias in the caller’s namespace, not a registration on the destination. Native local naming wrappers publish a prepared actor before its application goal runs. Browser publication follows completion of the creation call. A remote application may run before its caller-side alias is published, so publication is not an activation barrier. See register/2 for namespace and alias lifetimes.

Named remote creation requires a correlated spawn acknowledgement. An uncorrelated peer is rejected with remote_spawn_failed(uncorrelated_spawn_reply); unnamed creation retains legacy compatibility. Connection loss can raise remote_spawn_failed(connection_closed) while leaving the remote outcome unknown. Cleanup can request termination of a known remote pid but cannot undo remote side effects or guarantee cancellation after connection loss.

monitor(true) installs monitoring as part of creation. On termination the creator receives down(Pid,Ref,Reason); spawn-time monitoring uses Ref = Pid. link(true) is directional: parent termination stops linked children, without implying propagation from child to parent. Browser remote spawn installs caller-side monitoring when requested but does not forward links to the remote node.

Predicate: actors/1
actor
actors(-Pids) is det.

Binds Pids to the list of actor pids visible from the current execution context. In ordinary public client execution, this means the current actor or toplevel together with any actors that have been spawned on behalf of the same client interaction. Actors belonging to other clients are not included.

Note: Outside public client execution, for example in node-owned runtime code or administrative code, actors/1 returns the pids of all active local actors on the node.

Predicate: monitor/2
actor
monitor(+PidOrName, -Ref) is det.

Installs a monitor on an actor the caller may send to and returns a fresh reference in Ref. References use secure randomness and are never reissued; knowing a reference does not authorize removal of another actor’s monitor. The first argument may be a pid or a registered local name. When the monitored process terminates, the monitoring process receives a message of the form down(Pid,Ref,Reason).

Note: monitor(true) in spawn/3 installs monitoring before the child can terminate, preserving its actual exit reason. A monitor installed after termination is discharged with down(Pid,Ref,no_process).

Reasons include true for success, false for failure, exception(E) for an uncaught exception, and an explicit exit term. Loss of remote observation produces connection_closed; it discharges the monitor without proving actor death, and reconnection does not restore it. At the monitor boundary, an SWI error(Formal,Context) preserves Formal but replaces Context with a variable. Undefined-procedure errors also omit private generated actor-module qualifications.

Predicate: demonitor/1-2
actor
demonitor(+Ref) is det.
demonitor(+Ref, +Options) is det.

Stops only a monitor installed by the calling actor and identified by Ref. This is idempotent. There is only one valid option:

  • flush
    Non-blocking removal of all pending down(_,Ref,_) messages from the mailbox.
Predicate: register/2
actor
register(+Name, +Pid) is det.

Registers the actor identified by Pid under atom Name. A pid may have one ordinary name and, independently, one service name. An occupied name or already named pid is rejected; a missing or terminating local pid raises existence_error(process,Pid). Registering a remote pid does not establish that it is alive or install a monitor.

Namespace differences: Native SWI ordinary names are local to the caller’s client namespace. Native Trealla ordinary names are node-wide; SWI-WASM actors share their page’s ordinary-name namespace. The service namespace is separate in all cases. Native client teardown removes that client’s registrations and pending reservations and rejects late publication; removing a name does not terminate its actor.

Local termination removes ordinary registrations. Remote aliases are withdrawn on observed termination of the exact pid or loss of their connection; this does not prove remote death. SWI-WASM removes ordinary aliases for the disconnected node; native cleanup follows the connection’s known pids and preserves aliases belonging to other connections. Without an observed event, explicit unregister/1 may still be needed. Names rebound to another pid, service names and unrelated monitors are preserved.

In native ordinary registration, an already named pid raises process_already_has_a_name(Pid) and an occupied name raises name_is_in_use(Name). Native SWI namespaces normally follow the connection or session and are inherited by descendants; sharing an authenticated principal alone does not merge registries. Standalone native use defaults to a global namespace. Closed native namespaces reject late registration with permission_error(register,closed_namespace,Namespace).

Predicate: whereis/2
actor
whereis(+Name, -Pid) is det.

Binds Pid to the actor process associated with Name, or to undefined if no such registration exists.

A pending named creation returns undefined until publication. Lookup uses the ordinary namespace described under register/2.

Predicate: unregister/1
actor
unregister(+Name) is det.

Removes the association between the name and the process. The actor itself is not terminated. The operation is idempotent and succeeds without effect if Name is not registered.

Predicate: register_service/2
actor, owner only
register_service(+Name, +Pid) is det.

Publishes the live local actor identified by Pid under Name in the node's public service namespace. Name must be an atom, Pid must identify an actor on the publishing node, and there may be at most one published service with a given name on a node. If the name is already published, register_service/2 raises permission_error(register,service,Name), even when the existing entry denotes the same actor. Replacement is therefore explicit: the owner must first withdraw the old mapping.

The public service namespace is distinct from the ordinary registration namespace used by register/2; the same atom may occur in both without a collision. A qualified address Name@Node is resolved against the public service namespace of Node. whereis/2 consults only the ordinary namespace; owner-side code may inspect the service namespace with whereis_service/2.

Publication neither changes the actor's links nor places it under supervision. In particular, register_service/2 does not detach the actor from its parent. When the actor terminates, the node controller removes the service mapping atomically, so a published name never remains bound to a dead pid. A supervisor that starts a replacement actor must publish that actor again under the stable name.

Only code executing with node-owner authority may call this predicate. A call by any other principal raises permission_error(register,service,Name). A non-atom Name raises type_error(atom,Name); a Pid that does not identify a live actor raises existence_error(process,Pid); and an attempt to publish an actor on another node raises permission_error(register,service,Pid).

Predicate: whereis_service/2
actor, owner only
whereis_service(+Name, -Pid) is det.

Binds Pid to the live local actor published as Name, or to undefined if no such service is published. This predicate inspects only the public service namespace.

Only code executing with node-owner authority may call it; other callers receive permission_error(access,actor_service_registry,whereis_service(Name,Pid)). A non-atom Name raises type_error(atom,Name).

Predicate: unregister_service/1
actor, owner only
unregister_service(+Name) is det.

Withdraws Name from the node's public service namespace. This removes only the name: it neither terminates nor otherwise changes the actor that the name denoted. The operation is idempotent and succeeds without effect when no such service is published.

Only code executing with node-owner authority may call this predicate; other callers receive permission_error(unregister,service,Name). A non-atom name raises type_error(atom,Name).

Predicate: exit/1
actor
exit(+Reason) is det.

Terminates the calling process with Reason.

Predicate: exit/2
actor
exit(+Pid, +Reason) is det.

Terminates an actor in the caller’s ownership tree, identified by Pid, with Reason. A client targeting another tree receives error(permission_error(exit, actor, Pid), _). Raw host thread ids and aliases are never actor termination targets. For remote actors, the runtime routes this request through the remote node. Termination commits when the first exit reason is accepted; later exit and abort signals have no effect.

Predicate: !/2, send/2-3
actor
+PidOrName ! +Message is det.
send(+PidOrName, +Message) is det.
send(+PidOrName, +Message, +Options) is det.

Sends Message to the mailbox of the process identified as PidOrName. PidOrName may be a local pid, a local registered name, a global pid of the form Id@Node, or a published service address of the form Name@Node. A global pid may be a value returned by the runtime or a term constructed directly from a known identifier and node; the two are equivalent. Qualified service addresses are resolved only through the destination node's live service registry. If such a service is absent or the sender is not authorised to use it, the send succeeds without delivery and does not reveal which condition applied. By contrast, an unknown local registered name raises existence_error(actor_name,Name); a send to an unknown pid succeeds without delivery. Valid options for send/3 are:

  • delay(+Number)
    Delays the sending by a specified number of seconds. Default is 0.
  • id(+ID)
    ID is a user-supplied identifier that can be used by cancel/1 to stop the sending from taking place.

Portable actor application messages are acyclic ordinary Prolog terms. Atoms, strings, numbers, variables, lists, and compound terms are portable; variables arrive as fresh variables. Attributed variables, streams, and other non-text blob values must be encoded explicitly by the application. Remote delivery preserves these terms and their variable sharing; runtime guides describe their wire encoding. A double-quoted literal denotes a string in every profile: goals, options, answers, input and actor source are read with double_quotes set to string, whatever the host's default. Native local delivery may happen to carry additional host terms, but programs using them are outside the placement-independent contract.

Predicate: cancel/1
actor
cancel(+ID) is det.

Tries to cancel the sending of all delayed messages with the specified ID. This is best-effort only, since a message may already have been sent by the time the call is made.

Predicate: output/1-2
actor
output(+Data) is det.
output(+Data, +Options) is det.

Sends a message output(Pid,Data) to the target process. Pid is the pid of the current process. Valid option:

  • target(+Pid)
    Send the message to Pid. Default is the parent process.

Note that this is just a convenience predicate. Any actor may use !/2 to send any term to any process to which it has a pid.

Predicate: input/2-3
actor
input(+Prompt, -Data) is det.
input(+Prompt, -Data, +Options) is det.

Sends a message prompt(Pid,Prompt) to the target process and waits for its input. Prompt may be any Prolog term. Pid is the pid of the current process. Data will be bound to the term that the target process sends using respond/2. Valid option:

  • target(+Pid)
    Send the prompt message to Pid. Default is the current I/O target when one has been installed, or otherwise the parent process.
Predicate: respond/2
actor
respond(+Pid, +Input) is det.

Sends Input to the process identified by Pid as a response to a prompt(Pid,Prompt) message.

Predicate: receive/1-2
actor
receive(+Clauses) is nondet.
receive(+Clauses, +Options) is nondet.

Waits for, selects, and consumes one message from the calling process's mailbox. A call is single-message, but not necessarily single-solution. During one invocation it selects and consumes at most one message. Messages are considered in arrival order, and each message is tested against the receive clauses in textual order. The first message accepted by a clause is removed from the mailbox. This selection is committed: backtracking through the invocation never selects another message or another clause.

The selected clause body is ordinary Prolog code. The call as a whole therefore has the determinism of the fired body: a body may fail, succeed once, throw an exception, or yield several solutions. Choice points left by the body remain available, but they enumerate solutions of that same body; they do not inspect the mailbox again. The selected message remains consumed if the body fails or throws, and is not restored on backtracking. Thus the nondet declaration concerns the possible number of logical solutions, not the number of messages consumed by one invocation. For example, after one foo message has arrived, receive({foo -> member(X, [a,b])}) consumes that message once but can yield both X = a and X = b.

A cut in the selected body is scoped to that body, as if invoked through call/1; it cannot prune the caller’s choice points. Candidate matching and guard evaluation use tentative bindings, discarded when that candidate fails. Guards must be observationally free of side effects; the runtime need not enforce this and does not undo effects of a failing guard. A fallible external service should return explicit results if a guard must distinguish errors from ordinary non-matches.

Clauses has the following form:

{  Pattern1 [if Guard1] ->
         Body1 ;
   ...
   PatternN [if GuardN] ->
         BodyN
}

A clause accepts a message if its pattern matches the message and its optional guard succeeds. Matching is one-sided: the pattern must subsume the message, so a pattern never binds variables that occur in the message. A guard is evaluated for its first solution only, as if by once/1, and should be free of side effects. Bindings from the pattern and guard are in scope in the body. If a guard fails or raises an ordinary exception, that clause does not accept the message. Control exceptions (abort, termination, enforced limits) propagate out of receive/1-2, and the message being examined stays in the mailbox. A guard that checks a correlation reference or a pid should test it with == rather than bind it.

Messages accepted by no clause are deferred: they remain in the mailbox, without any change in their contents or relative order, and are available to later receive calls. receive({}) accepts no message and waits, subject to Options. Valid options:

  • timeout(+Number)
    Bounds the wait for an accepted message, in seconds. The value 0 inspects messages already in the mailbox without waiting for another. A positive timeout is converted once to an absolute deadline, so messages skipped during the scan do not restart the timeout. Default is no timeout.
  • deadline(+AbsoluteTime)
    Sets an absolute deadline in the same time scale as get_time/1. This is useful when several operations must share one time budget. A deadline that has already passed expires immediately. If both timeout/1 and deadline/1 are present, timeout/1 takes precedence.
  • on_timeout(+Goal)
    Called if the relative timeout or absolute deadline expires with no message accepted. Its success, failure, exception, and any choice points determine the outcome of the receive on the timeout path. Default is true. This option is only meaningful when timeout/1 or deadline/1 is present.
Predicate: flush/0
actor
flush is det.

Removes all messages currently pending in the mailbox of the calling process. Each removed message is rendered through the actor terminal-output path as a line of the form Shell got Message, where Message is the full Prolog term.

Note: flush/0 is primarily a shell-level inspection utility. It does not wait for future messages: once the mailbox is empty at the time of the call, it succeeds immediately.

Predicate: listing/0-1
isotope
listing is det.
listing(+What) is det.

listing/0 lists the content of the private database of the current actor process through the terminal-output path. Imported predicates and the injected I/O wrapper predicates are omitted.

listing/1 lists the predicates or clauses in the current process's private database selected by What, following the conventional Prolog meaning of listing/1. What may be a predicate indicator (Name/Arity or Name//Arity), a callable head pattern, a clause reference, or a list of such specifications. It does not provide access to another actor's private database.

Predicates for programming with toplevel actors

Predicate: toplevel_spawn/1-2
actor
toplevel_spawn(-Pid) is det.
toplevel_spawn(-Pid, +Options) is det.

Spawns a toplevel actor and binds Pid to its pid. All options accepted by spawn/3 are also accepted by toplevel_spawn/2. In addition, toplevel_spawn/2 accepts the following options:

  • session(+Boolean)
    If set to false, the toplevel actor terminates after having run a goal to completion. If true, further interaction is expected. Default is false in the actor API.
  • target(+Pid)
    Send all answer terms to Pid. Default is the pid of the parent.
  • name(+Name)
    Register the toplevel actor under Name in the local ordinary-name namespace.
  • time_limit(+SecondsOrInfinite)
    Bounds each continuous period spent executing a goal in PTCP state s2. On expiry the target receives error(Pid, error(resource_error(time), _)) and a session toplevel returns to s1, ready for another call. Time spent waiting for a continuation in s3 does not count; the running time limit starts again when a continuation resumes. Default is infinite in the actor API; a public node may impose a finite ceiling.
  • idle_limit(+SecondsOrInfinite)
    Bounds inactivity while a session toplevel waits for a call in state s1 or a continuation in state s3. On expiry the actor terminates normally, so a monitor observes down(Pid, Ref, true). Default is infinite in the actor API; a public node may impose a finite ceiling.

Both finite lifecycle limits must be positive numbers of seconds. A public client may request tighter values, but cannot weaken the node owner's ceilings. These limits are distinct from an ISOTOPE session HTTP request's timeout, which only bounds how long that request waits for the next queued event and does not abort the goal or terminate the session.

Options follow the common validation rules; session/1 is boolean, names are atoms, and finite lifecycle limits are positive numbers. Source loading follows the source conventions.

Predicate: toplevel_call/2-3
actor
toplevel_call(+Pid, +Goal) is det.
toplevel_call(+Pid, +Goal, +Options) is det.

Asks the toplevel Pid for solutions to Goal. Valid options are:

  • template(+Template)
    Template is a term sharing variables with Goal. By default, the template is identical to the goal.
  • offset(+Integer)
    Collect only the slice of solutions starting from Integer. Default is 0.
  • limit(+Integer)
    Restrict the length of the returned list of solutions to the positive integer Integer. If omitted, collect all solutions, subject to the node’s resource bounds.
  • once(+Boolean)
    When true, commits to the first returned slice and reports More = false, even if Goal has further solutions. Default is false. This option is useful primarily with limit/1.
  • target(+Pid)
    Send the answer term to Pid. Default is the value of target when passed as an option to toplevel_spawn/2.

Variables in Goal are not bound directly in the caller. Instead, solutions and other kinds of output are returned in the form of answer messages delivered to the mailbox of the target process:

  • success(Pid, Data, More)
    Pid is the pid of the toplevel process that succeeded in finding solutions to Goal. Data is a list holding instantiations of Template. More is either true or false, indicating whether the toplevel can return more solutions if toplevel_next/1-2 is called.
  • failure(Pid)
    Pid is the pid of the toplevel process that failed for lack of solutions.
  • error(Pid, Data)
    Pid is the pid of the toplevel throwing the error. Data is the error term.

A toplevel serves one controlling client at a time, and each call starts afresh: when it accepts Goal, it discards any toplevel_next/1-2, toplevel_stop/1 or input left over from an earlier query, that is, sent before the call; one sent after the call is kept. If the goal raises an exception after a finite limit has already collected some solutions, those solutions are delivered first as success(Pid, Data, true), and the error answers the following toplevel_next/1-2. A toplevel_stop/1 or once(true) in that state discards the error.

Answers are plain terms. A solution that still carries constraints, such as those left by dif/2, freeze/2 or CLP(FD), cannot be represented in an answer: printing it would drop the constraints. The toplevel then reports error(Pid, error(representation_error(constraints), _)) instead of the page, and the query ends. This holds whether the client is local or remote. A goal that needs such answers should bind the constrained variables, for example by labelling, or return the constraints as ordinary terms.

Predicates: toplevel_call_synch/3-4, toplevel_next_synch/2-3
actor
toplevel_call_synch(+Pid, :Goal, -Answer) is semidet.
toplevel_call_synch(+Pid, :Goal, -Answer, :Options) is semidet.
toplevel_next_synch(+Pid, -Answer) is semidet.
toplevel_next_synch(+Pid, -Answer, :Options) is semidet.

Send one command and collect its answer in the calling actor. Answers retain success(Pid,Data,More), failure(Pid) and error(Pid,Error); goal variables remain independent in the caller. Query errors are returned as answer terms rather than thrown by the wrapper. A private request reference prevents an old answer after a timeout from satisfying a later wait. Ordinary asynchronous answers and I/O are preserved. An asynchronous call or next uses ordinary answer messages.

The caller must be the answer target. An explicit target/1 must identify that same actor. Call options are template/1, offset/1, limit/1 and once/1; next accepts limit/1. Both accept receive options timeout/1 and on_timeout/1. Native SWI additionally accepts io_target/1; browser wrappers reject it. Trealla’s outbound correlated calls use the corresponding remote-client API; it does not expose these local wrapper names as an interchangeable public entry point. Options follow the common validation rules.

The default wait is unbounded. Without a callback, a receive timeout succeeds with Answer unbound. A timeout callback runs once in the caller’s context, retaining its bindings, failure and exceptions. Timeout does not stop the query; a stale correlated answer cannot satisfy a subsequent wait or extend its deadline. Observed termination throws toplevel_down(Reason). An answer is selected before output unification, so a mismatch consumes it and fails. The wait’s monitor is removed on every exit path, preserving unrelated monitors and messages.

Browser target restrictions: Both SWI-WASM runtimes accept concrete local integer pids (including Integer@localhost) and remote Integer@Node pids with atom node URIs. Aliases and legacy pid forms are unsupported. A remote peer must support correlated calls; otherwise the operation raises permission_error(use,toplevel_correlation,Node) before starting or advancing the query. Connection setup is outside the receive timeout. Asynchronous compatibility and remaining answer-fidelity limitations are described under remote execution.

These wrappers retain the toplevel’s single-client protocol. They provide neither concurrent-client coordination nor remote cancellation.

Predicate: toplevel_next/1-2
actor
toplevel_next(+Pid) is det.
toplevel_next(+Pid, +Options) is det.

Asks toplevel Pid for more solutions. Valid options:

  • limit(+Integer)
    Must be a positive integer. If omitted, retain the most recent finite slice size.
  • target(+Pid)
    Send the answer term to Pid. Default is the value of target from the previous call state.

The messages delivered to the target mailbox are the same as for toplevel_call/2-3.

Predicate: toplevel_stop/1
actor
toplevel_stop(+Pid) is det.

Asks toplevel Pid to stop searching for more solutions.

Predicate: toplevel_abort/1
actor
toplevel_abort(+Pid) is det.

Tells the local toplevel Pid to abort the currently running goal. Abort runs supported cleanup, bypasses recovery in client catch/3, and returns a persistent session to PTCP state s1 without terminating the actor. A session(false) toplevel terminates instead. An abort in s1 leaves a persistent session idle, one in s3 abandons the suspended solutions, and one that arrives after termination has been committed is ignored. Every abort that reaches a live toplevel, including one in s1, is acknowledged: the toplevel sends abort(Pid) to the client of its most recent call (or, before any call, to its spawn target), after any answers the aborted query had already sent. A client that waits for abort(Pid) before its next call therefore knows that every answer received before it belongs to the aborted query. An unknown or non-local pid has no effect.

Predicates for programming with supervisor actors

Predicate: supervisor_spawn/2-3
actor
supervisor_spawn(+ChildSpecs, -Pid) is det.
supervisor_spawn(+ChildSpecs, -Pid, +Options) is det.

Spawns a supervisor actor and starts its children. Supported options are:

  • strategy(+Strategy)
    One of one_for_one (default), one_for_all, or rest_for_one.
  • intensity(+Integer)
    Maximum number of restarts permitted within one period. Default is 1.
  • period(+Number)
    Restart-intensity window in seconds. Default is 5.
  • name(+Name)
    Register the supervisor under Name.

Other options are passed through to spawn/3.

Child specifications take the form child(Id, ChildOptions). Child options are:

  • start(+Goal)
    Required. Start goal for the child. The special form server(Pred,ServerOptions) starts a generic server child. The default initial state is []. It may be replaced with initial_state(+State). All remaining ServerOptions are passed to server_spawn/4.
  • restart(+Policy)
    One of permanent (default), transient, or temporary.
  • shutdown(+Shutdown)
    One of brutal_kill, infinity, or a timeout in seconds. The default is 5 for workers and infinity for supervisor children. With a timeout, a server child is first sent its stop request and receives exit(Pid, shutdown) only if it has not exited in time; other children receive exit(Pid, shutdown) at once.
  • type(+Type)
    worker (default) or supervisor.

Creation and child options follow the common validation rules. intensity/1 is a nonnegative integer; period/1 is a positive number, including fractional seconds. The complete initial child list, including recognised nested server and supervisor starts, is validated before creation. Specifications are acyclic, sibling ids are unique, and start/1 is required. Missing starts raise missing_start_option(Id); duplicate initial ids raise permission_error(duplicate,supervisor_child_id,Id). Validation checks callable starts and callbacks without executing them. Native ids may be ground terms; browser ids must be atoms. A named server child requires an atom id.

Native SWI admission limitation: Sandbox checking can reject a nested child-specification list that is still unbound when a query is submitted, even if an earlier conjunction would bind it before supervisor_spawn/2-3 runs. Writing that nested list explicitly avoids this limitation. Trealla accepts the runtime-bound form. This concerns query admission, not subtree replacement after a child terminates.

SWI-WASM child options additionally accept forwarded spawn settings and boolean significant/1 compatibility metadata; native child-specification options are limited to start/1, restart/1, shutdown/1 and type/1. Nested server/supervisor options take precedence over generated child names and child-level spawn settings. Shared variables and the original restart specifications are retained. significant/1 does not add an automatic shutdown policy.

A permanent child restarts after any termination, a transient child after failure or abnormal termination but not success (true), and a temporary child never restarts. one_for_one replaces the affected child; one_for_all restarts the whole group; rest_for_one restarts that child and later siblings. Replacements retain child order, dynamic additions append, successfully completed transient children retain an inactive specification, and temporary children are removed.

Startup rollback: Failed initial startup reclaims that attempt’s provisional children in reverse start order using their shutdown policies. A failed dynamic addition reclaims only its own provisional child and leaves existing siblings and supervisor state unchanged, allowing retry. These paths preserve unrelated monitors and messages, and cleanup errors do not replace the primary startup failure or prevent other cleanup attempts. An infinity shutdown policy may delay completion indefinitely. Startup here means creation, preparation and admission; a child terminating after successful creation follows its restart policy.

In native SWI and Trealla, ordinary initial startup failure retains init_failed and an initial exception retains its original error. Dynamic additions and explicit respawn return error(start_failed) for ordinary failure or error(Error) for an exception, leaving the supervisor available. Reserved runtime control transfers still propagate.

Restart failure: A failed explicit respawn rolls back only that attempt, retaining existing siblings and the inactive specification for retry. If an automatic replacement fails, provisional replacements are reclaimed, remaining children are stopped in reverse start order using their shutdown policies, and the supervisor exits with restart_failed(Id,Reason). Id identifies the replacement that failed; Reason is start_failed or its original exception. These paths preserve unrelated actors, monitors and messages; cleanup errors do not replace the primary failure or prevent other cleanup attempts.

Restart-intensity exhaustion: The restart budget is checked before replacement startup. Exhaustion starts no excess replacement, stops remaining recorded children in reverse start order using their shutdown policies, and exits with shutdown. An intensity(0) budget permits no automatic restarts. Cleanup preserves unrelated monitors and messages; ordinary cleanup errors do not replace the shutdown reason or prevent attempts to stop other children.

Startup reporting differences: Native creation acknowledges the supervisor before all child starts complete; monitor it for later initialization failure (init_failed for ordinary failure). Browser creation waits for startup and can raise error(supervisor_start_failed(Pid,Reason),supervisor_spawn/3); a JavaScript setup failure can appear as supervisor_startup_error(Message). Neither form establishes application-level readiness.

Child shutdown policies govern explicit termination, normal halt, rollback and group-restart stopping. brutal_kill stops immediately with reason kill. A recognised server start receives a graceful stop request and is forced down with reason shutdown if its numeric timeout expires. Zero and fractional timeouts are supported. Plain actors and nested supervisors receive direct termination with reason shutdown; recursive cooperative shutdown is not guaranteed. A stop acknowledgement alone does not establish completed termination.

These guarantees require the runtime to execute its cleanup paths. Forced Worker termination can bypass Prolog cleanup; losing a remote connection does not prove remote death, and an unacknowledged remote start can have an unknown outcome. No general guarantee is made here for cleanup after arbitrary supervisor exits. Synchronous request waits and their errors are described below.

  • supervisor_down(Reason)
  • supervisor_call_timeout(Sup, Request)

Supervisor request waits select the matching reply before unifying outputs; a mismatch consumes it and fails. Actor-based predicate generics

Predicate: parallel/1
actor
parallel(+Goals) is semidet.

Runs the proper list of independent goals Goals concurrently, using one monitored worker actor per goal. The call succeeds when every goal has produced its first solution and returns the resulting variable bindings. parallel([]) succeeds immediately. Further solutions are not enumerated on backtracking.

parallel/1 and first_solution/2-3 can be called directly in an ACTOR toplevel, with or without supplied source. Worker goals may use predicates supplied in the caller’s source.

If any goal fails, the remaining workers are terminated and the call fails. If any goal throws an exception, the remaining workers are terminated and the exception is rethrown. Result and monitor messages belonging to the workers are removed before the predicate returns, fails, or throws.

Worker cleanup covers partial startup failure, exceptions, caller interruption and abandonment of the call. Only the combinator’s workers and their result/monitor messages are reclaimed; unrelated actors, monitors and messages are preserved. This is local cleanup and does not cancel remote computations already requested by a worker. Browser hard Abort closes the shell’s combinator scopes, while ordinary actors outside those scopes can survive. Forced termination that bypasses runtime cleanup remains a limitation.

An unexplained worker exit is an error worker_exit(Pid,Reason); a worker’s reported exception is propagated as that exception. Workers are collected as they complete, without waiting in creation order. The first observed failure or error determines the outcome; scheduling can affect that choice, and there is no leftmost-goal precedence. After a result has been accepted, its termination notification only confirms that worker has stopped.

The goals must not depend on bindings or side effects produced by sibling goals. Actor creation and message copying add overhead, and the one-worker-per-goal model gives large goal lists a correspondingly large resource footprint.

A non-list Goals raises type_error(list, Goals). An element that is not callable raises the corresponding callable type error from its worker, which is propagated to the caller.

Predicate: first_solution/2-3
actor
first_solution(?Solution, +Goals) is semidet.
first_solution(?Solution, +Goals, +Options) is semidet.

Runs the proper list of alternative goals Goals concurrently in monitored worker actors and unifies Solution with the result produced by the first solver to succeed. Once a winner has been selected, all remaining workers are terminated and their result and monitor messages are removed. The predicate does not enumerate later solutions on backtracking, and an empty goal list fails.

The two-argument form continues after an individual solver fails and stops on the first exception. The three-argument form accepts:

  • on_fail(stop|continue)
    continue removes the failed solver and keeps waiting while alternatives remain; stop terminates all workers and fails immediately. Default is continue.
  • on_error(stop|continue)
    continue removes the solver that raised an exception and keeps waiting while alternatives remain; stop terminates all workers and rethrows the exception. Default is stop.

If all alternatives are removed under a continue policy, the predicate fails. Goals should not depend on side effects produced by sibling solvers.

A non-list Goals or Options raises type_error(list, Term). An action other than stop or continue is rejected: SWI reports type_error(oneof([stop,continue]),Action), while Trealla reports domain_error(first_solution_policy,Action). An unknown option raises domain_error(first_solution_option, Option).

The parallel/1 worker-cleanup and unexpected-exit rules also apply here. on_error/1 governs unexplained worker exits as well as exceptions. A winner is selected before output unification; even if the caller’s output does not match, remaining workers are cleaned up before the call fails.

Predicates for remote Prolog-style calls

Predicate: rpc/2-3
isobase
rpc(+URI, +Goal) is nondet.
rpc(+URI, +Goal, +Options) is nondet.

Executes a copy of Goal through the stateless /call endpoint of the node identified by URI, then unifies the local goal with each returned solution on backtracking. This remains a stateless call even when the destination is an ACTOR node: actor-only predicates such as self/1, spawn/1-3, and receive/1-2 are not available through rpc/2-3.

The first argument alone selects the execution node. localhost means the node on which rpc/2-3 is running. Source-loading options supply source for the call's temporary private database and do not change that target. For example, rpc('https://n2.example',Goal,[src_uri('https://n3.example')]) executes Goal on n2.example using source fetched from n3.example. The API options are listed below; the current runtime support differences follow the list:

  • limit(+Integer)
    A positive integer restricting the number of solutions retrieved per roundtrip. If omitted, request all solutions in one exchange.
  • once(+Boolean)
    When true, retrieves only the first slice and does not request later slices. Default is false.
  • timeout(+Number)
    Requests a timeout in seconds for goal execution on the destination node. The effective timeout is the minimum of this value and the node owner's configured timeout.
  • http_timeout(+Number)
    Sets the client-side HTTP transport timeout in seconds for each request. It does not change the destination node's execution timeout.
  • src_text(+AtomOrString)
    Loads source text into the temporary private database before calling Goal.
  • src_list(+ListOfClauses)
    Converts the clauses to source text and loads them into the temporary private database.
  • src_uri(+URI)
    Fetches source from URI and loads it into the temporary private database. This URI is a source location only.
  • src_predicates(+ListOfPredicateIndicators)
    Copies the caller's indicated predicates into the temporary private database.

Options follow the common validation rules. limit/1 is a positive integer; once/1 is boolean. Source options follow source-loading conventions. template/1 and offset/1 belong to promise/4 and are rejected by rpc/3.

Current HTTP client differences: SWI native and SWI-WASM support once/1 and separate remote execution timeout/1 from client transport http_timeout/1. Trealla currently rejects once/1 and http_timeout/1; its timeout/1 is a nonnegative number or infinite and bounds the HTTP transport, not destination execution. These are implementation differences; portable callers cannot yet rely on identical timeout options.

Native SWI additionally accepts request_header(Name=Value), authorization(basic(User,Password)), authorization(bearer(Token)) and user_agent(Text). Native Trealla accepts request headers, Basic authorization and user-agent settings, plus redirect(Boolean), max_redirect(NonnegativeInteger) and cacert_file(File); CA configuration requires a TLS-enabled build. Browser clients reject these native transport options.

Native SWI and SWI-WASM normalise negative execution and HTTP timeouts to zero. Native SWI also accepts none or an unbound requested execution timeout as unspecified. The Worker runtime also accepts none for an unspecified timeout; the compatibility main engine requires numbers when timeouts are supplied. Omission uses each runtime’s defaults.

Predicate: promise/3-4
isobase
promise(+URI, +Goal, -Ref) is det.
promise(+URI, +Goal, -Ref, +Options) is det.

Starts one asynchronous stateless call to node URI with Goal and returns a local promise reference in Ref. As with rpc/2-3, the first argument selects the execution node and localhost denotes the current node. Source-loading options populate the promised call's temporary private database; they do not change its execution node. It accepts the same limit/1, once/1, timeout/1, http_timeout/1, and src_*/1 options as rpc/3, together with:

  • template(+Template)
    Template is a term sharing variables with the goal. By default, the template is identical to the goal.
  • offset(+Integer)
    A nonnegative integer selecting the starting offset of the single solution slice collected by the promise. Default is 0.

The reference returned in Ref can later be used by yield/2-3 to collect the single answer term. Programs must not infer meaning from its digits or construct references themselves.

Options use the same validation and runtime-specific HTTP subset as rpc/3, plus arbitrary template/1 and nonnegative integer offset/1. Template variables remain shared with the goal, and the caller’s variables are not bound by remote execution. Collection, explicit disposal and five-minute expiry reclaim local promise resources; pending and ready but uncollected promises can expire. Late completion cannot recreate a disposed reference.

Ownership differences: Native SWI and Trealla restrict public promises to their owning client context; trusted standalone actors retain local sharing. Native SWI distinguishes WebSocket, interactive-session and delegated namespaces even for one authenticated principal. Its authenticated stateless HTTP calls use principal identity scoped to the node, while anonymous stateless calls use request-local ownership. Anonymous clients need a session or authentication to collect across requests. Trealla uses its existing client/HTTP ownership contexts; these are not interchangeable portable ownership tokens. Ending a native WebSocket client namespace disposes of its promises without terminating surviving actors. In SWI-WASM, each engine owns its own promise store: the compatibility main engine shares promises across its successive queries, and each spawned Worker has a separate store. Passing a reference to another engine grants no access; coincident numeric values denote that engine’s own promises. Replacing or destroying an engine destroys its references. Ownership transfer is unsupported.

Predicate: yield/2-3
isobase
yield(+Ref, -Answer) is det.
yield(+Ref, -Answer, +Options) is det.

Waits for the answer term from a previous call to promise/3-4. The reference is local to the runtime that created it; in SWI-WASM this means the creating engine, as described under promise/3-4. The answer is one of success(Data,More), failure, or error(Error), as returned by the stateless call endpoint. Valid options are:

  • timeout(+Number)
    Waits at most Number seconds for the promised answer. Default is no timeout.
  • on_timeout(+Goal)
    Calls Goal if the timeout expires before the answer is available.

A timeout does not cancel or consume the promise; a later call with the same reference may collect an answer that arrives afterward. If on_timeout/1 is omitted, the timeout path succeeds with Answer = timeout. A callback may bind the answer itself; otherwise it defaults to timeout. A failing callback raises error(timeout_callback_failed(Ref), Context). Unknown, consumed, expired or explicitly disposed references raise error(existence_error(promise, Ref), Context); references must be integers. Browser transport failures are delivered as error(rpc_error(Detail)) answers.

Options follow the common validation rules. timeout/1 requires a number (Trealla also accepts infinite) and on_timeout/1 requires a callable goal. Callback context and sharing with Answer are preserved. A native worker failure is delivered as an error answer rather than leaving the collector blocked.

Only one collector may wait on a reference at a time; a competing yield raises permission_error(collect,promise,Ref). Timeout, cooperative interruption or an exception before collection commits releases the collector and retains the promise. Collection consumes the selected answer before output unification; a mismatch therefore fails without making the answer available again. Disposal or expiry wakes a waiting collector with existence_error(promise,Ref), without invoking its timeout callback. Access from another ownership scope is treated as a missing reference.

promise_cleanup(+Ref) is det.

Native nodes are persistent and inbound-addressable and use native threads with hard termination, but have no DOM. Worker SWI-WASM actors have Web-Worker isolation and hard termination but share the page's lifetime, are not inbound-addressable, and have no DOM. The optional main-thread SWI-WASM engine has DOM access but cooperative engine isolation and no hard termination; it too shares the page's lifetime and initiates rather than accepts remote connections.

Availability gap: This capability predicate is implemented by native SWI and both SWI-WASM runtimes; native Trealla does not currently expose it.

Common error contract

Direct predicate calls throw errors. instantiation_error identifies insufficiently instantiated inputs; type_error/2 an incorrect type; domain_error/2 an unsupported value within a type; existence_error/2 a missing object; permission_error/3 an unauthorised operation; and resource_error/1 an unavailable bounded resource. Execution limits use error(resource_error(time),_).

Submitted-goal errors are reported as error(Pid,E) by a toplevel and error(E) by stateless calls. Monitors report uncaught actor exceptions as down(Pid,Ref,exception(E)). Boundary sanitisation can remove host-private context while retaining the portable formal error in Prolog-format responses and node-to-node term fields. Browser JSON display diagnostics are not a stable error-classification interface; transport representations and machine-readable codes are documented separately.

Actor I/O (Overrides)

The ambient stream I/O predicates of ISO Prolog are blacklisted. In their place, the actor runtime prelude injects local overrides that route output through the actor messaging layer:

Standard library and utility predicates

Nodes accepting general Prolog goals supply list relations member/2, memberchk/2, append/3, length/2, select/3, nth0/3-4 and nth1/3-4; integer relations between/3 and succ/2; and iteration/solution processing through maplist/2-8, foldl/4-6, call_nth/2, countall/2 and forall/2, subject to profile and sandbox restrictions.

memberchk/2 commits to its first match; maplist/2-8 applies a goal across corresponding list elements; foldl/4-6 also threads an accumulator. call_nth/2 numbers solutions from one; countall/2 counts them. forall/2 tests its second goal for every solution of its first and exports no bindings.

Predicate: make_ref/1
actor
make_ref(-Ref) is det.

Produces a fresh opaque correlation reference suitable for messages. Compare references with == and do not depend on their representation. This does not install a monitor or request a notification.

Predicate: sleep/1
isobase
sleep(+Seconds) is det.

Suspends execution for nonnegative, possibly fractional seconds, without consuming mailbox messages. Control signals or execution limits may interrupt it. An actor may also express a delay with a timed receive/2.

Node introspection

Predicate: node_setting/2
all public profiles
node_setting(?Key, ?Value) is nondet.

Enumerates publicly visible settings of the node servicing the request. With Key bound, succeeds for its visible current value. Unknown or unavailable keys fail. Credentials, principal policies, and shared-database source are not exposed.

  • General: url, profile, sandbox, auth, timeout, rate_window_seconds.
  • Stateless API: max_inflight_calls, max_term_text_bytes, max_call_requests_per_window.
  • Private database: max_load_text_bytes, load_uri_allowed_origins.
  • Session API: max_sessions_per_principal, max_session_spawns_per_window.
  • Actor API: max_ws_actors_per_principal, max_ws_frame_bytes, max_ws_commands_per_window.

API-specific keys are visible only when their corresponding built-in family is enabled for the node's profile. This predicate reads settings; it does not modify them.

Remote execution and compatibility

Remote execution-time exhaustion is reported as error(resource_error(time), _), and memory exhaustion as error(resource_error(space), _). RPC clients propagate these exceptions. A client transport timeout does not establish that the remote computation has stopped.

Compatible peers preserve complete ordinary Prolog answer terms, variable sharing, quoted atoms, strings and exceptions. Public asynchronous answers remain success(Pid,Slice,More), failure(Pid) and error(Pid,Error). Older peers may reconstruct answers from display fields and report remote_error(Text), losing some term fidelity. After full-term support is negotiated, missing or invalid payloads produce remote_answer_protocol_error(missing_term) or remote_answer_protocol_error(invalid_term) rather than silently degrading. This compatibility applies to both native and browser clients; it does not relax the portable term subset described under send/2-3.

Monitor references retain their complete value, independently of pid display abbreviation. Correlated synchronous operations require peer support and fail explicitly when unavailable; ordinary asynchronous operations retain legacy compatibility. A timeout or connection loss is not remote cancellation.

Page sizes are caller-controlled: HTTP requests, persistent-toplevel calls and next honour limit(N) without silently reducing it to an owner solution-count cap. A finite goal may finish with fewer answers; applicable resource limits still apply. Without an explicit limit, Trealla no longer splits results at its former owner count cap.

HTTP paging offsets advance by the number of answers actually returned, rather than the requested limit. A short non-final page therefore does not skip answers or a pending error.

Native Trealla applies the owner’s time_limit/1 to each complete HTTP page computation, covering startup, offset skipping, collection and lookahead. Each request has a fresh budget; time spent idle in the continuation cache does not count. Expiry raises error(resource_error(time), _). Response serialization and socket writing are outside this deadline.

Native Trealla applies the owner’s stack_limit/1 independently to actors and HTTP/WebSocket connection handling, including page collection. This is not a total node-memory or response-byte budget. Recoverable HTTP exhaustion is reported as error(resource_error(space), _); failure before a usable request context or during error reporting may close the connection instead.

Native Trealla reclaims the local computation for a failed or interrupted HTTP page request when the handler unwinds. A cached continuation remains available if writing its page response fails. When the continuation cache exceeds its size limit, it evicts the oldest entries and stops their suspended computations; a computation already checked out by another request remains that request's responsibility. This does not add immediate disconnect detection, cache expiry or cleanup after forced runtime cancellation that bypasses Prolog unwinding.

The runtime guides linked in the introduction document wire envelopes, capability negotiation, terminal acknowledgements, source-fetch machinery and session replay. Those mechanisms support this API rather than define additional language predicates.
