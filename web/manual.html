Web Prolog manual

This manual describes the Web Prolog language and APIs implemented by the current demonstrator. It should be read as a snapshot of a design in progress, not as a final language specification: terminology, predicate interfaces, and behaviour are still tentative and may change as the implementation evolves.

The classification shown beside each entry identifies the minimum public node profile in which the predicate is available, or another relevant execution context. ISOBASE provides general stateless Prolog calls, ISOTOPE adds persistent toplevel sessions, and ACTOR adds the full stateful actor-messaging model. The profiles are cumulative, so an entry marked isotope is also available in ACTOR. The classification concerns the client language, not predicates used internally to implement a profile. Entries additionally marked owner only are reserved for code running with node-owner authority and are not available to ordinary client code.

This document reproduces the book's manual appendix in HTML form. Each predicate entry carries an HTML anchor using its predicate indicator so that entries can be linked directly.

Predicates for programming with core actors

Predicate: self/1
actor
self(-Pid) is det.

Binds Pid to the process identifier of the calling process.

Note: A pid is an actor address whose canonical global form is Id@Node, where Id is assigned by Node. This ordinary Prolog compound is part of the language contract: programs may copy, store, construct, decompose, compare, and serialise it. A shell may omit @Node for a pid on the shell's own node, but this is only a local abbreviation. Constructing a pid does not create an actor, confirm that it is live, or grant access to it; an operation reaches an actor only when the pair designates that actor and the node authorises the operation. Arithmetic on a numeric Id has no defined actor-level meaning. Browser runtimes reserve localhost as the local-node designator. Worker actors are therefore presented as, for example, 2159438818@localhost, and the optional main-thread SWI-WASM engine is presented as main@localhost.

Predicate: spawn/1-3
actor
spawn(+Goal) is det.
spawn(+Goal, -Pid) is det.
spawn(+Goal, -Pid, +Options) is det.

Creates a new Web Prolog actor process running Goal. A principal subtree quota raises error(resource_error(actors), _). Lost contact during remote creation raises error(remote_spawn_failed(connection_closed), _); the remote outcome is unknown and retrying side effects needs duplicate suppression.

Valid options are:

  • node(+URI)
    Creates the process locally or on a remote compatible node. Default is localhost.
  • monitor(+Boolean)
    If true, monitoring is installed as part of process creation. Default is false.
  • link(+Boolean)
    If true, installs directional parent-to-child link cleanup. Default is true. On a public node, only its owner may use link(false); detachment transfers ownership to the node and sends output to its log.
  • src_text(+AtomOrString)
    Loads the clauses specified by a Web Prolog source text into the actor's private Prolog database before calling Goal.
  • src_list(+ListOfClauses)
    Converts the clauses to source text and loads them into the actor's private Prolog database before calling Goal.
  • src_uri(+URI)
    Loads the clauses specified by a file path, file URI, or HTTP(S) URI into the actor's private Prolog database before calling Goal.
  • src_predicates(+ListOfPredicateIndicators)
    Loads the local predicates denoted by ListOfPredicateIndicators into the actor's private Prolog database before calling Goal.

Both SWI-WASM runtimes validate plain spawn/3 options before collecting source, reserving a pid, creating a worker, dispatching remotely, or installing a monitor. Options must be unary terms in a proper list. Unknown names and wrong arities raise error(domain_error(spawn_option,Option),context(spawn/3,_)); invalid values raise type, domain, or instantiation errors with the same context. Every occurrence is checked, including later duplicates. The first ordinary option still wins, source options remain additive with each runtime's existing collection order, and validation does not bind or copy option variables.

Browser node/1 requires an atom or string, and link/1 and monitor/1 require booleans. Browser spawning also accepts browser-local aliases through name(+Atom), which plain native spawn/3 does not accept. src_text/1 requires an atom or string, src_list/1 a proper list, and src_predicates/1 a proper list of indicators with atom names and nonnegative integer arities. Both runtimes accept atom/string src_uri/1, including server, supervisor and toplevel creation. The creating engine asks the browser page to fetch Prolog source before child creation; remote spawning forwards the fetched text.

Worker Prolog source collection preserves its groups: text entries, lists, copied predicates, then URI texts, retaining option order within each group. Repeated URIs are fetched separately. The compatibility main engine retains source-option list order. The existing URI origin allowlist, credentials: same-origin and browser CORS rules still apply; arbitrary origins, files and authentication options are not added. Fetch errors propagate without creating a child. Failed or interrupted creation releases its reserved name, and late fetch completion cannot resume abandoned creation. In-flight source-fetch cancellation remains separate. Statechart XML source selection is unchanged.

Both SWI-WASM runtimes reserve the browser-local name/1 before local or supported remote creation and publish its pid only after the complete call succeeds. This also applies to local server, supervisor, toplevel and statechart creation. An occupied or pending name raises error(permission_error(register,actor_name,Name),PI), with the creation predicate in PI, without creating an actor. Pending reservations are hidden from whereis/2. Startup failure or exception releases the reservation and reclaims actors and monitors created by that attempt, including detached and nested children. Links, pid sharing, monitor references, duplicate-option precedence and successful reply formats are preserved. Normal early termination still returns the pid and requested down notification, but leaves no stale name. Publication does not guarantee continued actor liveness or application-level readiness.

Browser actors share the page’s ordinary-name namespace; each pid may have one ordinary name and independently one service name. Wrappers remove their name option internally while holding the reservation. Supported remote paths, including plain spawn and toplevel creation, now use the same reservation. The name is an alias in the browser, not a registration or service publication on the remote node.

Remote spawn replies use the existing request_id field for correlation. Named creation rejects replies that omit it, with a diagnostic containing remote_spawn_failed(uncorrelated_spawn_reply); the ambiguous pid cannot safely be claimed or terminated. Unnamed requests retain the existing FIFO fallback for peers that omit ids. Reordered tagged replies settle only their own requests, and cleanup exits are tagged so their errors cannot consume another spawn reply.

The coordinator records an acknowledged pid before resuming the caller. Failed setup, output mismatch, interruption or creator termination releases the reservation, withdraws startup-owned monitors, and requests termination of known remote actors while preserving the original outcome and unrelated monitors. A late correlated acknowledgement after cancellation cannot publish and receives a best-effort termination request; the pending record lasts until acknowledgement or connection close. Cancellation before connection readiness prevents late dispatch. Observed termination or connection loss before commit raises error(remote_spawn_failed(terminated),PI) or error(remote_spawn_failed(connection_closed),PI). Publication approval stays rollback-owned until commit.

Startup guards end at commit. Published ordinary remote aliases are cleaned up on observed events as described below. Remote effects may occur before publication and cannot be undone. Losing the connection before an acknowledgement can leave an unknown remote outcome. This adds no implicit ongoing monitoring, activation handshake or guaranteed remote cancellation.

In both browser runtimes, an observed remote down withdraws ordinary aliases for that exact pid, even when there is no matching local monitor. Connection loss withdraws ordinary aliases for that node. Removal precedes monitor notification delivery, so handlers can reuse the names immediately. Each current binding is checked: old termination events preserve names reassigned to another pid. Local names, other nodes, service registrations, application messages and unrelated monitors are preserved; pending startup guards remain in force.

No implicit monitors or background checks are added. Without an observed event, callers may still need unregister/1. Connection loss does not establish remote actor death. Existing remote registration rules still permit explicit registration after cleanup; no retirement or ownership policy is added.

Nonvariable target/1 and io_target/1 remain accepted compatibility options; plain browser spawn retains its existing coordinator output routing. Remote browser spawn continues to send the goal and source and can install a caller-side monitor. It does not register a name on the remote node, forward links, or redirect output. The shared browser server/supervisor wrappers separate their own settings and child-specification fields before forwarding spawn options, preserving the original child specifications. Wrapper entry validation is described under each creation predicate; child-specification validation is described under supervisor creation.

Note: In spawn(+Goal,-Pid,+Options), the option monitor(true) installs monitoring as part of process creation. When the child terminates, the parent receives a message down(Pid,Ref,Reason) where Pid is the terminated actor, Reason is its exit reason, and Ref identifies the monitor instance. For monitoring created via monitor(true), the current implementation uses Ref = Pid.

Note: The semantics of link(true) are directional: if a parent spawns a child with linking enabled, termination of the parent causes linked children to be terminated. The link does not imply symmetric bidirectional exit propagation.

Note: It is possible to pass an arbitrary number of the src_* options to spawn/3, and possibly more than one instance of each variant. To ensure that clauses end up in a well-defined order, they are converted into Prolog source text before being loaded into the database. The order of clauses and directives in the resulting source text is determined by the order of the src_* options in the option list.

Predicate: actors/1
actor
actors(-Pids) is det.

Binds Pids to the list of actor pids visible from the current execution context. In ordinary public client execution, this means the current actor or toplevel together with any actors that have been spawned on behalf of the same client interaction. Actors belonging to other clients are not included.

Note: Outside public client execution, for example in node-owned runtime code or administrative code, actors/1 returns the pids of all active local actors on the node.

Predicate: monitor/2
actor
monitor(+PidOrName, -Ref) is det.

Installs a monitor on an actor the caller may send to and returns a fresh reference in Ref. References use secure randomness and are never reissued; knowing a reference does not authorize removal of another actor’s monitor. The first argument may be a pid or a registered local name. When the monitored process terminates, the monitoring process receives a message of the form down(Pid,Ref,Reason).

Note: monitor(true) in spawn/3 installs monitoring before the child can terminate, preserving its actual exit reason. A monitor installed after termination is discharged with down(Pid,Ref,no_process).

In native JSON down events, Ref is preserved independently of the actor address. A pid-shaped reference retains its full node qualifier even when the node is the sender itself; compound references use quoted Prolog term text. Actor-pid normalization and display abbreviation do not apply to references. This allows browser clients to correlate remote spawn-time monitor(true) notifications without weakening reference matching.

Reasons include true for success, false for failure, exception(E) for an uncaught exception, and an explicit exit term. Loss of remote observation produces connection_closed; it discharges the monitor without proving actor death, and reconnection does not restore it. At the monitor boundary, an SWI error(Formal,Context) preserves Formal but replaces Context with a variable. Undefined-procedure errors also omit private generated actor-module qualifications.

Predicate: demonitor/1-2
actor
demonitor(+Ref) is det.
demonitor(+Ref, +Options) is det.

Stops only a monitor installed by the calling actor and identified by Ref. This is idempotent. There is only one valid option:

  • flush
    Non-blocking removal of all pending down(_,Ref,_) messages from the mailbox.
Predicate: register/2
actor
register(+Name, +Pid) is det.

Registers an actor process under a name, where Name is an atom and Pid identifies the actor. The association between the name and the pid is removed when the process terminates.

In SWI-WASM, an ordinary name reserved by a pending local or remote creation is unavailable to explicit registration, including from another actor. The separate service namespace is unaffected. Unregister cannot remove a pending creation reservation; only its creating engine’s matching token can publish or release it. Normal late cleanup cannot remove a committed name.

Predicate: whereis/2
actor
whereis(+Name, -Pid) is det.

Binds Pid to the actor process associated with Name, or to undefined if no such registration exists.

In SWI-WASM, a name reserved by a pending local or remote creation returns undefined until publication.

Predicate: unregister/1
actor
unregister(+Name) is det.

Removes the association between the name and the process. The actor itself is not terminated. The operation is idempotent and succeeds without effect if Name is not registered.

Predicate: register_service/2
actor, owner only
register_service(+Name, +Pid) is det.

Publishes the live local actor identified by Pid under Name in the node's public service namespace. Name must be an atom, Pid must identify an actor on the publishing node, and there may be at most one published service with a given name on a node. If the name is already published, register_service/2 raises permission_error(register,service,Name), even when the existing entry denotes the same actor. Replacement is therefore explicit: the owner must first withdraw the old mapping.

The public service namespace is distinct from the ordinary registration namespace used by register/2; the same atom may occur in both without a collision. A qualified address Name@Node is resolved against the public service namespace of Node. whereis/2 consults only the ordinary namespace; owner-side code may inspect the service namespace with whereis_service/2.

Publication neither changes the actor's links nor places it under supervision. In particular, register_service/2 does not detach the actor from its parent. When the actor terminates, the node controller removes the service mapping atomically, so a published name never remains bound to a dead pid. A supervisor that starts a replacement actor must publish that actor again under the stable name.

Only code executing with node-owner authority may call this predicate. A call by any other principal raises permission_error(register,service,Name). A non-atom Name raises type_error(atom,Name); a Pid that does not identify a live actor raises existence_error(process,Pid); and an attempt to publish an actor on another node raises permission_error(register,service,Pid).

Predicate: whereis_service/2
actor, owner only
whereis_service(+Name, -Pid) is det.

Binds Pid to the live local actor published as Name, or to undefined if no such service is published. This predicate inspects only the public service namespace.

Only code executing with node-owner authority may call it; other callers receive permission_error(access,actor_service_registry,whereis_service(Name,Pid)). A non-atom Name raises type_error(atom,Name).

Predicate: unregister_service/1
actor, owner only
unregister_service(+Name) is det.

Withdraws Name from the node's public service namespace. This removes only the name: it neither terminates nor otherwise changes the actor that the name denoted. The operation is idempotent and succeeds without effect when no such service is published.

Only code executing with node-owner authority may call this predicate; other callers receive permission_error(unregister,service,Name). A non-atom name raises type_error(atom,Name).

Predicate: exit/1
actor
exit(+Reason) is det.

Terminates the calling process with Reason.

Predicate: exit/2
actor
exit(+Pid, +Reason) is det.

Terminates an actor in the caller’s ownership tree, identified by Pid, with Reason. A client targeting another tree receives error(permission_error(exit, actor, Pid), _). Raw host thread ids and aliases are never actor termination targets. For remote actors, the runtime routes this request through the remote node. Termination commits when the first exit reason is accepted; later exit and abort signals have no effect.

Predicate: !/2, send/2-3
actor
+PidOrName ! +Message is det.
send(+PidOrName, +Message) is det.
send(+PidOrName, +Message, +Options) is det.

Sends Message to the mailbox of the process identified as PidOrName. PidOrName may be a local pid, a local registered name, a global pid of the form Id@Node, or a published service address of the form Name@Node. A global pid may be a value returned by the runtime or a term constructed directly from a known identifier and node; the two are equivalent. Qualified service addresses are resolved only through the destination node's live service registry. If such a service is absent or the sender is not authorised to use it, the send succeeds without delivery and does not reveal which condition applied. By contrast, an unknown local registered name raises existence_error(actor_name,Name); a send to an unknown pid succeeds without delivery. Valid options for send/3 are:

  • delay(+Number)
    Delays the sending by a specified number of seconds. Default is 0.
  • id(+ID)
    ID is a user-supplied identifier that can be used by cancel/1 to stop the sending from taking place.

Portable actor application messages are acyclic ordinary Prolog terms. Atoms, strings, numbers, variables, lists, and compound terms are portable; variables arrive as fresh variables. Attributed variables, streams, and other non-text blob values must be encoded explicitly by the application. The demonstrator validates this subset whenever serialization is required, and writes such terms as canonical text: quoted, without operator syntax, portray hooks or numbervars, and with explicit variable names. A double-quoted literal denotes a string in every profile: goals, options, answers, input and actor source are read with double_quotes set to string, whatever the host's default. Native local delivery may happen to carry additional host terms, but programs using them are outside the placement-independent contract.

Predicate: cancel/1
actor
cancel(+ID) is det.

Tries to cancel the sending of all delayed messages with the specified ID. This is best-effort only, since a message may already have been sent by the time the call is made.

Predicate: output/1-2
actor
output(+Data) is det.
output(+Data, +Options) is det.

Sends a message output(Pid,Data) to the target process. Pid is the pid of the current process. Valid option:

  • target(+Pid)
    Send the message to Pid. Default is the parent process.

Note that this is just a convenience predicate. Any actor may use !/2 to send any term to any process to which it has a pid.

Predicate: input/2-3
actor
input(+Prompt, -Data) is det.
input(+Prompt, -Data, +Options) is det.

Sends a message prompt(Pid,Prompt) to the target process and waits for its input. Prompt may be any Prolog term. Pid is the pid of the current process. Data will be bound to the term that the target process sends using respond/2. Valid option:

  • target(+Pid)
    Send the prompt message to Pid. Default is the current I/O target when one has been installed, or otherwise the parent process.
Predicate: respond/2
actor
respond(+Pid, +Input) is det.

Sends Input to the process identified by Pid as a response to a prompt(Pid,Prompt) message.

Predicate: receive/1-2
actor
receive(+Clauses) is nondet.
receive(+Clauses, +Options) is nondet.

Waits for, selects, and consumes one message from the calling process's mailbox. A call is single-message, but not necessarily single-solution. During one invocation it selects and consumes at most one message. Messages are considered in arrival order, and each message is tested against the receive clauses in textual order. The first message accepted by a clause is removed from the mailbox. This selection is committed: backtracking through the invocation never selects another message or another clause.

The selected clause body is ordinary Prolog code. The call as a whole therefore has the determinism of the fired body: a body may fail, succeed once, throw an exception, or yield several solutions. Choice points left by the body remain available, but they enumerate solutions of that same body; they do not inspect the mailbox again. The selected message remains consumed if the body fails or throws, and is not restored on backtracking. Thus the nondet declaration concerns the possible number of logical solutions, not the number of messages consumed by one invocation. For example, after one foo message has arrived, receive({foo -> member(X, [a,b])}) consumes that message once but can yield both X = a and X = b.

Clauses has the following form:

{  Pattern1 [if Guard1] ->
         Body1 ;
   ...
   PatternN [if GuardN] ->
         BodyN
}

A clause accepts a message if its pattern matches the message and its optional guard succeeds. Matching is one-sided: the pattern must subsume the message, so a pattern never binds variables that occur in the message. A guard is evaluated for its first solution only, as if by once/1, and should be free of side effects. Bindings from the pattern and guard are in scope in the body. If a guard fails or raises an ordinary exception, that clause does not accept the message. Control exceptions (abort, termination, enforced limits) propagate out of receive/1-2, and the message being examined stays in the mailbox. A guard that checks a correlation reference or a pid should test it with == rather than bind it.

Messages accepted by no clause are deferred: they remain in the mailbox, without any change in their contents or relative order, and are available to later receive calls. receive({}) accepts no message and waits, subject to Options. Valid options:

  • timeout(+Number)
    Bounds the wait for an accepted message, in seconds. The value 0 inspects messages already in the mailbox without waiting for another. A positive timeout is converted once to an absolute deadline, so messages skipped during the scan do not restart the timeout. Default is no timeout.
  • deadline(+AbsoluteTime)
    Sets an absolute deadline in the same time scale as get_time/1. This is useful when several operations must share one time budget. A deadline that has already passed expires immediately. If both timeout/1 and deadline/1 are present, timeout/1 takes precedence.
  • on_timeout(+Goal)
    Called if the relative timeout or absolute deadline expires with no message accepted. Its success, failure, exception, and any choice points determine the outcome of the receive on the timeout path. Default is true. This option is only meaningful when timeout/1 or deadline/1 is present.
Predicate: flush/0
actor
flush is det.

Removes all messages currently pending in the mailbox of the calling process. Each removed message is rendered through the actor terminal-output path as a line of the form Shell got Message, where Message is the full Prolog term.

Note: flush/0 is primarily a shell-level inspection utility. It does not wait for future messages: once the mailbox is empty at the time of the call, it succeeds immediately.

Predicate: listing/0-1
isotope
listing is det.
listing(+What) is det.

listing/0 lists the content of the private database of the current actor process through the terminal-output path. Imported predicates and the injected I/O wrapper predicates are omitted.

listing/1 lists the predicates or clauses in the current process's private database selected by What, following the conventional Prolog meaning of listing/1. What may be a predicate indicator (Name/Arity or Name//Arity), a callable head pattern, a clause reference, or a list of such specifications. It does not provide access to another actor's private database.

Predicates for programming with toplevel actors

Predicate: toplevel_spawn/1-2
actor
toplevel_spawn(-Pid) is det.
toplevel_spawn(-Pid, +Options) is det.

Spawns a toplevel actor and binds Pid to its pid. All options accepted by spawn/3 are also accepted by toplevel_spawn/2. In addition, toplevel_spawn/2 accepts the following options:

  • session(+Boolean)
    If set to false, the toplevel actor terminates after having run a goal to completion. If true, further interaction is expected. Default is false in the actor API.
  • target(+Pid)
    Send all answer terms to Pid. Default is the pid of the parent.
  • name(+Name)
    Register the toplevel actor under Name in the local ordinary-name namespace.
  • time_limit(+SecondsOrInfinite)
    Bounds each continuous period spent executing a goal in PTCP state s2. On expiry the target receives error(Pid, error(resource_error(time), _)) and a session toplevel returns to s1, ready for another call. Time spent waiting for a continuation in s3 does not count; the running time limit starts again when a continuation resumes. Default is infinite in the actor API; a public node may impose a finite ceiling.
  • idle_limit(+SecondsOrInfinite)
    Bounds inactivity while a session toplevel waits for a call in state s1 or a continuation in state s3. On expiry the actor terminates normally, so a monitor observes down(Pid, Ref, true). Default is infinite in the actor API; a public node may impose a finite ceiling.

Both finite lifecycle limits must be positive numbers of seconds. A public client may request tighter values, but cannot weaken the node owner's ceilings. These limits are distinct from an ISOTOPE session HTTP request's timeout, which only bounds how long that request waits for the next queued event and does not abort the goal or terminate the session.

Both SWI-WASM runtimes validate the complete option list before source collection or setup. session/1 requires a boolean, names require atoms, and finite lifecycle limits require positive numbers; infinite remains valid. Every duplicate is checked, while defaults and first-occurrence precedence remain unchanged, including each runtime's existing local/remote defaults. Unknown options raise domain_error(spawn_option,Option); invalid values raise type, domain, or instantiation errors with toplevel_spawn/2 in the context. Both runtimes support URI source loading through the browser fetch path described under spawn/3.

Predicate: toplevel_call/2-3
actor
toplevel_call(+Pid, +Goal) is det.
toplevel_call(+Pid, +Goal, +Options) is det.

Asks the toplevel Pid for solutions to Goal. Valid options are:

  • template(+Template)
    Template is a term sharing variables with Goal. By default, the template is identical to the goal.
  • offset(+Integer)
    Collect only the slice of solutions starting from Integer. Default is 0.
  • limit(+Integer)
    Restrict the length of the returned list of solutions to the positive integer Integer. If omitted, collect all solutions, subject to the node’s resource bounds.
  • once(+Boolean)
    When true, commits to the first returned slice and reports More = false, even if Goal has further solutions. Default is false. This option is useful primarily with limit/1.
  • target(+Pid)
    Send the answer term to Pid. Default is the value of target when passed as an option to toplevel_spawn/2.

Variables in Goal are not bound directly in the caller. Instead, solutions and other kinds of output are returned in the form of answer messages delivered to the mailbox of the target process:

  • success(Pid, Data, More)
    Pid is the pid of the toplevel process that succeeded in finding solutions to Goal. Data is a list holding instantiations of Template. More is either true or false, indicating whether the toplevel can return more solutions if toplevel_next/1-2 is called.
  • failure(Pid)
    Pid is the pid of the toplevel process that failed for lack of solutions.
  • error(Pid, Data)
    Pid is the pid of the toplevel throwing the error. Data is the error term.

A toplevel serves one controlling client at a time, and each call starts afresh: when it accepts Goal, it discards any toplevel_next/1-2, toplevel_stop/1 or input left over from an earlier query, that is, sent before the call; one sent after the call is kept. If the goal raises an exception after a finite limit has already collected some solutions, those solutions are delivered first as success(Pid, Data, true), and the error answers the following toplevel_next/1-2. A toplevel_stop/1 in that state discards the error.

Answers are plain terms. A solution that still carries constraints, such as those left by dif/2, freeze/2 or CLP(FD), cannot be represented in an answer: printing it would drop the constraints. The toplevel then reports error(Pid, error(representation_error(constraints), _)) instead of the page, and the query ends. This holds whether the client is local or remote. A goal that needs such answers should bind the constrained variables, for example by labelling, or return the constraints as ordinary terms.

Predicates: toplevel_call_synch/3-4, toplevel_next_synch/2-3
actor
toplevel_call_synch(+Pid, :Goal, -Answer) is semidet.
toplevel_call_synch(+Pid, :Goal, -Answer, :Options) is semidet.
toplevel_next_synch(+Pid, -Answer) is semidet.
toplevel_next_synch(+Pid, -Answer, :Options) is semidet.

Send one command and collect its answer in the calling actor. Answers retain success(Pid,Data,More), failure(Pid) and error(Pid,Error); goal variables remain independent in the caller. A private request reference prevents an old answer after a timeout from satisfying a later wait. Ordinary asynchronous answers and I/O are preserved. An asynchronous call or next uses ordinary answer messages.

Both SWI-WASM runtimes support concrete local pids (an integer or Integer@localhost) and remote Integer@Node pids with an atom node URI. Aliases and experimental legacy pid forms remain unsupported. Remote commands require web-prolog-sync-v1 on the actual socket; otherwise they raise error(permission_error(use,toplevel_correlation,Node),_) before starting or advancing a query, even with timeout(0). Support is checked before monitoring and again on the sending socket. Connection setup is outside the receive timeout. Call query options are template/1, offset/1, limit/1 and once/1; next accepts limit/1. Both accept timeout/1, on_timeout/1 and target/1 identical to the waiting caller. The caller is always the answer target. All duplicate options are checked, first occurrence wins, and templates and callbacks retain sharing. Unknown options raise the corresponding toplevel_call_synch_option or toplevel_next_synch_option domain error. Native wrappers additionally support io_target/1; browser wrappers reject it.

The browser offers the existing native correlation subprotocol. If the upgrade fails before opening, it retries without a subprotocol for asynchronous compatibility; synchronous operations remain unavailable on that connection. Asynchronous routing and paging are unchanged; negotiated answer fidelity is described below. Synchronous calls use the actor-term transport with the waiting engine as answer target, returning complete tagged Prolog terms with nonground sharing and exception terms preserved. Timeout leaves the remote computation running. Later synchronous waits discard stale tagged answers for the same pid while preserving ordinary asynchronous answers and I/O. Cancellation, concurrent-client coordination, aliases and browser io_target/1 support remain separate.

Both SWI-WASM runtimes request answer_terms:true in the browser transport hello. Supporting nodes acknowledge it and send canonical term payloads for asynchronous successes and query errors. For negotiated peers, main-engine asynchronous calls request the existing format(prolog) to retain the supplied template rather than a display bindings dictionary; Worker actor-term calls already retain it. The receiving engine parses the complete solution list or exception once, preserving variable sharing, distinct variables, quoted atoms, strings and literal '$VAR'/1 terms. Public success(Pid,Slice,More), failure(Pid) and error(Pid,Error) reply formats remain unchanged. Existing actor-message replies already carry complete terms. I/O, monitor delivery, synchronous correlation and connection ownership are unchanged.

Peers without the acknowledgement retain the existing display-field reconstruction and remote_error(Text) fallback, with their fidelity limitations.   • strategy(+Strategy)
    One of one_for_one (default), one_for_all, or rest_for_one.

    Maximum number of restarts permitted within one period. Default is 1.

Other options are passed through to spawn/3.

    One of permanent (default), transient, or temporary.
  • shutdown(+Shutdown)
    One of brutal_kill, infinity, or a timeout in seconds. The default is 5 for workers and infinity for supervisor children. With a timeout, a server child is first sent its stop request and receives exit(Pid, shutdown) only if it has not exited in time; other children receive exit(Pid, shutdown) at once.

A permanent child restarts for any reason; a temporary child never restarts. Restarts remain subject to the configured intensity limit. Browser ordering, bookkeeping and shutdown are described below.

Both SWI-WASM runtimes preserve child start order across restarts. one_for_one replaces the failed child in place; one_for_all restarts all children in order; rest_for_one restarts only the failed child and later siblings, leaving earlier records and pids unchanged. Every duplicate is checked without copying or binding values; defaults, first-occurrence precedence, original restart specifications and variable sharing remain unchanged. Nested server/supervisor options retain precedence over the generated child name and child-level spawn settings. Browser shutdown/1 is honoured as described below; type/1 selects its default. significant/1 remains compatibility metadata. Validation itself does not execute shutdown or add automatic supervisor-exit cleanup. Runtime startup failures and rollback remain separate from validation.

A child startup exception is reported as error(supervisor_start_failed(Pid,Reason),supervisor_spawn/3). The existing readiness timeout also rolls back the caller’s startup attempt. Cleanup errors do not replace the startup error. Startup success does not establish application-level readiness. Known remote pids receive best-effort termination requests; a lost connection before a pid is returned can leave the remote outcome unknown. Recursive graceful shutdown and broader lifecycle work remain separate. Startup rollback remains an immediate cleanup path.

The remaining recorded children, including detached children, are stopped in reverse start order using their shutdown policies before the supervisor exits with reason shutdown. Counting, period pruning and threshold rules are unchanged for all three strategies. A cleanup failure or exception preserves the intended exit reason and allows attempts for other children, but cannot guarantee termination of the affected child. Unrelated actors, messages and explicit monitors are preserved. An infinity policy can delay exit; existing forced-termination and remote-observation qualifications apply. General cleanup after arbitrary supervisor exits remains separate.

In both browser runtimes, explicit respawn rolls back failed replacement startup, retains the inactive specification, and returns error(start_failed) for failure or error(Error) for an exception; success retains ok. Automatic replacements for one restart event share a startup journal. Cleanup must not replace the original reason. Unrelated actors and explicit monitors are preserved. There is no new retry loop; infinity shutdown can delay the failure exit. Initial readiness reporting does not send a second startup-failure notification for later restart errors. General supervisor-exit handling remains separate.

The default is 5 seconds for workers, or infinity when type(supervisor) is specified. Plain actors and nested supervisors receive direct termination with reason shutdown; recursive cooperative shutdown is not added.

Shutdown installs a private monitor before requesting stop, waits for its down notification, and removes that monitor and its tagged stop reply on every exit path. A stop acknowledgement alone is not completion. Unrelated monitors, application messages and public replies are preserved. Normal supervisor halt stops children in reverse start order; group restart stopping order and replacement start order are unchanged. Stopped records, counts and public reply formats are preserved.

Browser supervisor requests for child addition, termination, deletion, respawn, inspection and supervisor_halt/1 install a fresh private monitor before sending. They select the matching reply before unifying outputs; a mismatch consumes the reply and fails. Successful reply formats are unchanged. Observed termination throws supervisor_down(Reason); the existing ten-second reply wait now throws supervisor_call_timeout(Sup,Request) on expiry. The timeout starts after sending, does not bound connection setup, and does not cancel the requested operation or collect a later reply. Cleanup withdraws and flushes only the private monitor on success, failure, exception, interruption, cut or mismatch; unrelated monitors and application messages remain available.

The request wait is separate from the internal shutdown deadline. Both supervisor_halt/1 and supervisor_stop/1 use a tagged stop request and succeed after child shutdown. Their ten-second wait can raise supervisor_call_timeout(Sup,stop) without cancelling shutdown; multiple child deadlines or shutdown(infinity) can exceed that caller wait. A separate monitor is still required to observe the supervisor’s own termination. Legacy direct '$sup_stop'(From) requests retain their reply(true) acknowledgement. Forced Worker termination does not guarantee Prolog cleanup handlers execute, and remote connection loss does not prove remote death. Automatic supervisor-exit cleanup and broader lifecycle guarantees remain separate.

Actor-based predicate generics

Predicate: parallel/1
actor
parallel(+Goals) is semidet.

Runs the proper list of independent goals Goals concurrently, using one monitored worker actor per goal. The call succeeds when every goal has produced its first solution and returns the resulting variable bindings. parallel([]) succeeds immediately. Further solutions are not enumerated on backtracking.

If any goal fails, the remaining workers are terminated and the call fails. If any goal throws an exception, the remaining workers are terminated and the exception is rethrown. Result and monitor messages belonging to the workers are removed before the predicate returns, fails, or throws.

Both SWI-WASM runtimes track these workers in a private scope before launch. A later startup failure reclaims workers already created and preserves the original error. Caller interruption, including Stop in the UI, and cuts also initiate cleanup of the remaining scoped workers. Cleanup preserves unrelated actors, monitors, and messages. Normal collection waits for coordinator cleanup where needed; cleanup during unwinding does not await JavaScript promises. This covers local workers and does not cancel remote work they may already have requested. In the worker-based UI, hard Abort closes the shell's combinator scopes before replacing the shell. Ordinary actors created outside those scopes remain alive and are listed in the survivor notice.

The goals must not depend on bindings or side effects produced by sibling goals. Actor creation and message copying add overhead, and the one-worker-per-goal model gives large goal lists a correspondingly large resource footprint.

A non-list Goals raises type_error(list, Goals). An element that is not callable raises the corresponding callable type error from its worker, which is propagated to the caller.

Predicate: first_solution/2-3
actor
first_solution(?Solution, +Goals) is semidet.
first_solution(?Solution, +Goals, +Options) is semidet.

Runs the proper list of alternative goals Goals concurrently in monitored worker actors and unifies Solution with the result produced by the first solver to succeed. Once a winner has been selected, all remaining workers are terminated and their result and monitor messages are removed. The predicate does not enumerate later solutions on backtracking, and an empty goal list fails.

The two-argument form continues after an individual solver fails and stops on the first exception. The three-argument form accepts:

  • on_fail(stop|continue)
    continue removes the failed solver and keeps waiting while alternatives remain; stop terminates all workers and fails immediately. Default is continue.
  • on_error(stop|continue)
    continue removes the solver that raised an exception and keeps waiting while alternatives remain; stop terminates all workers and rethrows the exception. Default is stop.

promise(+URI, +Goal, -Ref) is det.
promise(+URI, +Goal, -Ref, +Options) is det.

Starts one asynchronous stateless call to node URI with Goal and returns a local promise reference in Ref. As with rpc/2-3, the first argument selects the execution node and localhost denotes the current node. Source-loading options populate the promised call's temporary private database; they do not change its execution node. It accepts the same limit/1, once/1, timeout/1, http_timeout/1, and src_*/1 options as rpc/3, together with:

  • template(+Template)
    Template is a term sharing variables with the goal. By default, the template is identical to the goal.
  • offset(+Integer)
    A nonnegative integer selecting the starting offset of the single solution slice collected by the promise. Default is 0.

The reference returned in Ref can later be used by yield/2-3 to collect the single answer term. Programs must not infer meaning from its digits or construct references themselves.

Both SWI-WASM runtimes validate options before source loading or promise creation, using the browser subset described under rpc/3, plus template/1 and offset/1. Unknown options or wrong arities raise error(domain_error(promise_option, Option), Context). Template variables remain shared with the goal; validation does not copy or bind them.

Both SWI-WASM runtimes expire a reference 300 seconds after creation, including pending requests and ready but uncollected answers. Expiry is checked on access as well as by timer, so background timer delays do not extend validity. Collection and disposal reclaim the local record and timers; disposal also releases pending local transport resources. Late completion cannot recreate a disposed reference.

In SWI-WASM, promises belong to the engine that created them. Each Worker has its own store; the compatibility main engine shares one store across successive queries. Spawned actors use separate Worker stores, including actors spawned from the main engine. A later query in the same surviving engine may collect or dispose of its promises. Passing a reference to another actor does not transfer access. Numeric references are not globally unique: a coincident number denotes only the receiving engine’s own promise. These boundaries preserve existing behaviour; ownership transfer remains unsupported. Store isolation is not a security sandbox against trusted JavaScript with access to the main engine’s page.

Predicate: yield/2-3
isobase
yield(+Ref, -Answer) is det.
yield(+Ref, -Answer, +Options) is det.

Waits for the answer term from a previous call to promise/3-4. The reference is local to the runtime that created it; in SWI-WASM this means the creating engine, as described under promise/3-4. The answer is one of success(Data,More), failure, or error(Error), as returned by the stateless call endpoint. Valid options are:

  • timeout(+Number)
    Waits at most Number seconds for the promised answer. Default is no timeout.
  • on_timeout(+Goal)
    Calls Goal if the timeout expires before the answer is available.

A timeout does not cancel or consume the promise; a later call with the same reference may collect an answer that arrives afterward. If on_timeout/1 is omitted, the timeout path succeeds with Answer = timeout. A callback may bind the answer itself; otherwise it defaults to timeout. A failing callback raises error(timeout_callback_failed(Ref), Context). Unknown, consumed, expired or explicitly disposed references raise error(existence_error(promise, Ref), Context); references must be integers. Browser transport failures are delivered as error(rpc_error(Detail)) answers.

Both SWI-WASM runtimes validate the complete option list before waiting or collecting an answer. timeout/1 must contain a number and on_timeout/1 a callable goal. Unknown options or wrong arities raise error(domain_error(yield_option, Option), Context). Invalid options leave a valid promise available for a later yield and do not execute the callback. Callback qualification and sharing with the answer variable are preserved.

Both SWI-WASM runtimes allow one active collector per reference; a competing yield raises permission_error(collect,promise,Ref). Timeout, interruption or an exception before collection commits releases the claim and retains the answer. The claim is released before the timeout callback runs. Collection commits when Prolog resumes after the wait; a later output mismatch still consumes that selected answer. Disposal or expiry wakes an existing collector with existence_error(promise,Ref), without invoking the timeout callback. A cooperative interruption preserves the reference in its existing engine; destroying or replacing a Worker destroys its local references.

Predicate: promise_cleanup/1
isobase
promise_cleanup(+Ref) is det.

In both SWI-WASM runtimes, explicitly disposes of a local promise, releasing its stored answer, timers, waiters and pending local transport resources. The reference must be an integer. Cleanup is idempotent, including for unknown or already consumed, expired or disposed references. A subsequent yield raises existence_error(promise,Ref). Aborting the browser-side HTTP fetch does not guarantee cancellation of execution on the remote node. In SWI-WASM, cleanup consults only the calling engine’s store; it cannot dispose of another engine’s promise. If the same number exists locally, it denotes that local promise. Ownership transfer and native-style client namespace teardown remain separate.

Predicate: runtime_property/1
isobase
runtime_property(?Property) is nondet.

Enumerates properties of the host runtime. This predicate reports capabilities; it does not alter the Web Prolog profile or the semantics of the predicates above. Defined properties are:

  • implementation(swi_native|swi_wasm_worker|swi_wasm_main)
  • persistent(+Boolean)
  • inbound_addressable(+Boolean)
  • dom(+Boolean)
  • actor_isolation(native_thread|web_worker|cooperative_engine)
  • hard_termination(+Boolean)

Native nodes are persistent and inbound-addressable and use native threads with hard termination, but have no DOM. Worker SWI-WASM actors have Web-Worker isolation and hard termination but share the page's lifetime, are not inbound-addressable, and have no DOM. The optional main-thread SWI-WASM engine has DOM access but cooperative engine isolation and no hard termination; it too shares the page's lifetime and initiates rather than accepts remote connections.

HTTP and WebSocket conventions

These wire conventions complement the predicate API above and the book's Appendix D.

Results and source loading

Remote execution-time exhaustion is reported as error(resource_error(time), _); memory exhaustion as error(resource_error(space), _). RPC clients propagate these exceptions without a wrapper. The context is elided in normal display. A client transport timeout is distinct and does not establish that the remote computation has stopped.

In JSON success events, data is a list of binding objects whose values are Prolog-text strings: for example, {"X":"42"}. Default JSON query formatting replaces an explicit template with the visible named query variables. HTTP format=prolog returns a Prolog answer term and honors the template. WebSocket format(prolog) honors the template but retains a JSON envelope with Prolog-term strings in its data array. A down event's reason is Prolog term text. Integer monitor references within JavaScript's exact-integer range are JSON numbers; larger integers are decimal strings. Compound references are quoted Prolog term text with their complete structure and node qualifiers preserved, independently of the event's actor-pid formatting.

Supply source through spawn options. HTTP /toplevel_call still accepts changed, nonempty src_text for compatibility; empty or unchanged source does not reload. WebSocket toplevel_call rejects a src_text field even when empty. Its canonical options string accepts only template/1, offset/1, limit/1, once/1, and format/1. Defaults are the goal, 0, no solution-count limit, false, and json, respectively. Goal and options are parsed together. A WebSocket toplevel_next frame may include a JSON integer limit; omission inherits the current limit.

HTTP sessions force session(true); WebSocket toplevel spawn defaults to session(false). HTTP polling retrieves one queued event without advancing the solution sequence. Its timeout does not abort the goal. An HTTP abort replies only after the toplevel has acknowledged it, with an event of type abort. Every session request's response carries a Web-Prolog-Seq header numbering the event it returned. A client that did not receive a response may repeat the request with a Web-Prolog-Ack header holding the last number it did receive; if the lost response is the session's latest event, the node sends it again instead of running the command a second time. A session's former owner that addresses it after it has ended or been reclaimed receives an error whose code field is session_lost. The transport's statechart_trace setting defaults to false and is stored and acknowledged, but the current delivery code does not consult it to suppress traces. Use the statechart's trace/1 option to control generation.

Browser transport extensions

{"command":"transport_hello","version":1,
 "browser_pids":true,"io_ack":true}

The node answers with type:"transport_welcome", protocol:"web_prolog_browser_actor", version:1, and both capability flags set to true. Flags in the welcome advertise support; each extension is enabled only when requested in the hello.

With browser_pids enabled, qualified browser-local pids embedded in goals, templates, and messages receive connection-scoped return routes. Bare numbers, atoms, and source strings remain data. Replies arrive as:

{"type":"actor_message","target":"2159438818@localhost",
 "message":"reply(ok)"}

With io_ack enabled, terminal output arrives inside an acknowledgement request:

{"type":"io_request","request_id":"opaque-reference",
 "event":{"type":"output","pid":123,"data":"hello"}}

After accepting the output, reply on the same connection:

{"command":"browser_io_reply","request_id":"opaque-reference",
 "status":"ok"}

The alternative status is error. The actor waits for acceptance; an error, connection closure, or a 30-second acknowledgement timeout raises an I/O error. Late replies are discarded. This acknowledges acceptance, not browser painting. Prompts and query answers retain their ordinary event forms. Without this extension, output arrives directly as an output event.

WebSocket-created actors have a connection lifecycle monitor in addition to any explicit client monitor. Its down event carries a node-generated reference. Closing the connection terminates its actors and revokes browser return routes.
