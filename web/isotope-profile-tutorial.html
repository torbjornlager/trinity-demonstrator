Familiar Prolog

The programming language has not changed. Start with the same relational query used in the ACTOR tutorial:

?- append(Xs,Ys,[a,b,c]).

Use ;, the space bar or Next for further answers. The difference between profiles is how the computation is hosted and controlled, not how append/3 behaves.

What ISOTOPE keeps

N2 creates a private toplevel actor for the browser session. Calls made through that toplevel share state and an answer continuation. Output, input and Abort also have an ongoing session to which they can belong.

Session-local state

Make a fact, then ask for it in a separate query:

?- assertz(saved(isotope)).

?- saved(What).

The second call can see the first call's update because both run in the same private session. Other clients do not share it.

I/O and control

?- writeln('Hello from N2').

Output appears while the goal runs. A non-terminating goal can be interrupted with the red Abort button because the client has a persistent toplevel to address.

What ISOTOPE removes

ISOTOPE has a session actor internally, but application programs cannot create or address independent actors. In the Examples drawer, actor programs and SXML statecharts are therefore struck out: they are visible for comparison, but N2 cannot run them.

These ACTOR queries illustrate the boundary:

?- self(Pid).

?- spawn(writeln(hello), Pid).

?- receive({Message -> true}).

N2 reports that these actor operations are unavailable in the ISOTOPE profile. There is no application-visible pid or mailbox, no actor spawn, messaging, monitoring, linking, server behaviour or statechart actor.

When to choose ISOTOPE

ISOTOPE's main advantages are:

  • a private database and answer continuation across calls;
  • interactive input and output;
  • the ability to abort a running computation; and
  • ordinary HTTP infrastructure without a persistent WebSocket.

It suits interactive query services, private workspaces, conversational tools, configuration flows and other applications that need memory, I/O or cancellable work across several calls, but do not need independently running processes or server-initiated messages.

Compared with ACTOR, its HTTP request/response contract is simpler. Compared with ISOBASE, it requires the server to retain sessions, the client to manage their pids, and polling to retrieve events. That can still be unnecessary machinery for independent, function-like queries.

Continue the recommended path. Select N1 and open The ISOBASE profile tutorial. It keeps ordinary Prolog and stateless remote calls, but removes session state, I/O and Abort. If you want to study N2's request choreography first, take the ISOTOPE API tutorial.
