The ISOTOPE API

A short tour of Web Prolog's semi-stateful HTTP protocol. A persistent toplevel actor supplies state, while the browser still initiates every exchange.

First, spawn a toplevel

POST /toplevel_spawn
Content-Type: application/json

{ "options": "[session(true)]" }
{ "type": "spawned", "pid": 4384261893 }

The returned pid names a private, long-lived Prolog toplevel. Subsequent requests must carry it.

The same query, one answer at a time

?- append(Xs,Ys,[a,b,c]).

GET /toplevel_call?pid=4384261893&goal=append(Xs,Ys,[a,b,c])&limit=1&format=json
{
  "type": "success",
  "pid": 4384261893,
  "data": [{ "Xs": "[]", "Ys": "[a,b,c]" }],
  "more": true
}

The continuation lives inside the toplevel, so the next request names it rather than repeating the goal:

GET /toplevel_next?pid=4384261893&limit=1&format=json
{
  "type": "success",
  "pid": 4384261893,
  "data": [{ "Xs": "[a]", "Ys": "[b,c]" }],
  "more": true
}

What the session adds

Separate calls share the toplevel's private dynamic database. For example, an assertion made in one call remains visible in the next:

?- assertz(saved(api)), saved(X).

Output and prompts also belong to the session. HTTP cannot push them spontaneously, so the client retrieves events with /toplevel_poll and answers prompts with /toplevel_respond. Use /toplevel_stop to discard an answer continuation and /toplevel_abort to interrupt a running goal; node idle limits reclaim abandoned sessions.

Select API traffic in the Logger before pressing CALL. The session choreography—spawn, call, next and stop—is the defining feature to watch.

For executable browser code, compare the answer-paging demo and the prompt-and-response demo.

Advantages and disadvantages

AdvantagesDisadvantages
Private state and interactive I/O without a persistent network connection; ordinary HTTP remains friendly to familiar infrastructure. The client must track session pids and their lifecycle; polling and multi-request choreography add latency and complexity; idle sessions consume server resources until reclaimed.

Choose ISOTOPE when calls need memory or toplevel interaction, but HTTP request/response is operationally preferable. Choose ACTOR when the server must push events immediately or several actors must share a live channel.
